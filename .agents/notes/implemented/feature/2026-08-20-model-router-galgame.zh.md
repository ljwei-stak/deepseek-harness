# Agent Note: Model Router GALGame 插件与桌面端分发

Status: implemented

[English](2026-08-20-model-router-galgame.md) | 中文

## Problem

接入多个大模型 provider 的用户需要一种可见、可审计的方式，为每次请求选择性价比合适的模型，把复杂工作分配给多个模型，并在桌面客户端继续使用同一会话。原版 Harness 对话界面不会把模型分配呈现为 GAL 存档，也没有可安装的 Windows 与 Linux 本地运行时桌面发行方式。

## Decision

仓库以可移除的 Harness 插件形式提供 `plugins/model-router-galgame`。Host 扩展识别任务类型和复杂度，结合基准质量、任务专长、价格、延迟和风险对已发现的模型路由排序，并把复杂工作组织为分析、执行和汇总阶段。Client 扩展把会话中记录的分配结果呈现为 GAL 视窗，支持动态人物、存档、日志、附件、Markdown/KaTeX、费用估计，以及集体合作和单独会话。

插件通过普通会话消息记录简洁的路由说明和阶段报告，不请求或展示模型私有思维链。persona 指令只进入最终回答阶段，不能改变路由、工具、权限、代码、公式或证据处理。

`desktop/` 中的 Electron 客户端允许用户选择托管工作区，或解压内置的 Harness 本地运行时。各平台构建脚本会内置对应的 Node.js 可执行文件和便携 pnpm 启动器，再生成 Windows 安装程序或 x64 Debian、RPM 程序包。Windows 发布工具还会生成独立插件包、更新清单、安装包分片和 SHA256 列表。生成的运行时与安装包不进入 Git 历史，而是作为 Release 资产或短期 CI 产物发布。

插件设置页只检查 `ljwei-stak/deepseek-harness` 的稳定 Release。一键更新会在完整客户端可更新时选择客户端安装包，因为其中已经包含同版本插件；客户端已是最新版时才选择独立插件更新。两个手动入口仍然保留，每项原生操作都需要确认。插件更新先核验哈希、包身份、必要文件和声明的最低客户端/运行时版本，再保存到用户数据目录中的版本化目录；只有完整写入后才原子切换 `active.json` 指针。本地启动会在活动版本和内置插件中选择较新且兼容的版本，再原子复制到 Harness profile，因此内置旧插件不会覆盖在线更新。校验或 profile 复制失败时，原活动版本仍可继续使用。

Windows 完整客户端更新会下载或复用清单指定的 Release 分片，重建安装包，核验完整安装包 SHA256，并且只在全部检查通过后启动。Linux 会引导用户打开 Releases 页面，由系统包管理器安装 DEB 或 RPM，不在 Electron 内请求提权。API Key、provider 设置、会话和插件版本都位于应用安装目录之外。纯网页部署可以查看项目与 Releases 页面，但不能修改本机文件。

根目录 README 和插件 README 标注第三方创意与人物图片来源。人物图片不作为 MIT 许可的项目代码声明，商业使用或再分发前需要单独核对权利。

## Alternatives considered

**修改核心 agent loop。** 这种方式会让实验性路由和界面行为耦合到所有 Harness profile。插件方案保持功能可移除，并复用现有模型和会话扩展点。

**集体合作固定使用一个模型。** 这种方式会掩盖任务专长和成本差异，也无法形成多模型协作。分阶段候选排序会显示每项分配和回退结果。

**把桌面程序包和本地运行时提交进 Git。** 这些生成文件体积大，会永久膨胀仓库历史。Release 资产和短期 CI 产物可以提供下载，同时避免源码克隆携带每个版本的构建产物。

**在已安装客户端内执行 `git pull` 或 Sync Fork。** 源码更新无法定义彼此兼容的插件、运行时和桌面端组合，还会要求用户端携带仓库凭据与构建工具。版本化 Release 资产把维护者同步后的分支作为发布点，而不会把用户客户端变成 Git 工作树。

**只替换 profile 中的插件目录。** 桌面运行时启动时会复制内置插件，因此只改 profile 可能被覆盖，也可能让新插件加载到不兼容的 Harness 运行时。持久版本目录、兼容性字段和原子 profile 启用使独立插件更新可以长期保留并可回退。

**展示模型推理轨迹。** 私有思维链不是可审计性的必要条件，也不是稳定接口。插件改为展示评分输入、任务分配、费用、阶段报告和已观察到的失败。

## Consequences

插件可以独立于 Harness 核心演进，并按 profile 安装或删除。路由结果可以根据目录和问题复现，实际可执行模型由实时 provider 目录决定。独立插件发布仍受其最低客户端和运行时版本限制；不兼容时必须先更新完整客户端。Windows、Debian 与 RPM 程序包即使共享桌面版本，也必须分别进行原生构建。每个公开版本都需要内部一致的资产；失败或中断的下载会占用用户数据目录空间，但不会替换可用安装。基准质量与定价是显式目录输入，来源更新后也必须更新这些值。第三方视觉素材继续受各自许可条件约束。
